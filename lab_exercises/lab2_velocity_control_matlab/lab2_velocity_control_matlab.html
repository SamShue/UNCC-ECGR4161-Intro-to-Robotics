Lab 2: MATLAB Velocity Control

In this lab, you will bridge the gap between high-level motion commands and low-level hardware actuation using MATLAB and ROS Toolbox. Instead of implementing the controller inside the romi_base Python package, you will run the astar_bridge node on the Raspberry Pi and implement a PI controller in MATLAB that publishes wheel PWM commands while subscribing to encoder feedback from the bridge.

The goal is to learn the control loop itself: measure wheel speed from encoders, compare it to a target speed, tune Kp and Ki, and send updated PWM values until the robot tracks the desired motion.

Required Materials

  • Romi32U4 robot with Raspberry Pi 4B
  • Raspberry Pi image prepared from Lab 1
  • Windows laptop with MATLAB installed
  • ROS Toolbox installed in MATLAB
  • WSL2 with ROS 2 Humble installed
  • 6x AA batteries

Background

What Changes in This MATLAB Version

  • You do not modify the ROS 2 controller node in romi_base.
  • You run only the Pi-side bridge node: astar_bridge.
  • Your MATLAB script publishes to /wheel_pwm and subscribes to /encoder_ticks.
  • If you choose to display status, you may also publish to /leds.

Topics Provided by the Bridge

  • /encoder_ticks with std_msgs/Int32MultiArray containing left and right encoder counts.
  • /wheel_pwm with std_msgs/Int16MultiArray containing left and right PWM values.
  • /leds with std_msgs/Int16MultiArray containing red, yellow, and green LED values.

Important: This lab focuses on controller tuning in MATLAB. Keep the robot elevated for the first tests, start with low PWM magnitudes, and always send a final stop command [0, 0] before ending your session.

Procedure

1. Prepare the Robot and Pi

  1. Use the Lab 1 golden image workflow so the Raspberry Pi is already configured with Ubuntu, ROS 2, and the ROMI bridge support.
  2. Mount the Pi on the Romi, insert batteries, and connect to the robot’s Wi-Fi network.
  3. SSH into the Pi and start the bridge node:

2. Open MATLAB and Create Your Controller Script

Install and launch MATLAB, sign in with your charlotte.edu credentials, and verify that ROS Toolbox is installed. Then create a MATLAB script named romi_lab2_pi_controller.m.

3. Understand the Control Loop

Your MATLAB script should perform the following loop:

  1. Read encoder counts from /encoder_ticks.
  2. Convert encoder counts into measured wheel speed.
  3. Compare measured speed to your target wheel speed.
  4. Compute PWM using a PI controller.
  5. Publish the updated PWM to /wheel_pwm.
  6. Repeat at a fixed control interval.

4. MATLAB Starter Script

Use the script below as your starting point. It provides the ROS 2 publishers and subscribers you need, along with a PI controller scaffold. Your job is to tune the gains and verify stable tracking.

% romi_lab2_pi_controller.m
% MATLAB PI controller for ROMI Lab 2

clear;
clc;

setenv('ROS_DOMAIN_ID', '0');

node = ros2node('/romi_lab2_pi_controller');
encSub = ros2subscriber(node, '/encoder_ticks', 'std_msgs/Int32MultiArray');
pwmPub = ros2publisher(node, '/wheel_pwm', 'std_msgs/Int16MultiArray');
ledPub = ros2publisher(node, '/leds', 'std_msgs/Int16MultiArray');

pwmMsg = ros2message(pwmPub);
ledMsg = ros2message(ledPub);

% Controller targets
leftTargetMps = 0.10;
rightTargetMps = 0.10;

% Tuning parameters
kp = 450.0;
ki = 120.0;
maxPwm = 300;

% Robot constants (adjust only if your course provides updated values)
wheelDiameterM = 0.07;
ticksPerRev = 1440.0;
wheelCircumferenceM = pi * wheelDiameterM;

% State
integralLeft = 0.0;
integralRight = 0.0;
prevTicks = [];
prevTime = tic;

% Warm-up indication
ledMsg.data = int16([0, 1, 0]);
send(ledPub, ledMsg);

fprintf('Starting ROMI PI control loop...\n');

while true
    if encSub.NumMessagesAvailable == 0
        pause(0.01);
        continue;
    end

    encMsg = receive(encSub, 1.0);
    currentTicks = double(encMsg.data(:));

    if numel(currentTicks) < 2
        warning('Expected two encoder values [left, right].');
        continue;
    end

    dt = toc(prevTime);
    prevTime = tic;
    if dt <= 0
        dt = 1e-3;
    end

    if isempty(prevTicks)
        prevTicks = currentTicks;
        continue;
    end

    deltaTicks = currentTicks - prevTicks;
    prevTicks = currentTicks;

    leftDistanceM = (deltaTicks(1) / ticksPerRev) * wheelCircumferenceM;
    rightDistanceM = (deltaTicks(2) / ticksPerRev) * wheelCircumferenceM;

    leftSpeedMps = leftDistanceM / dt;
    rightSpeedMps = rightDistanceM / dt;

    leftError = leftTargetMps - leftSpeedMps;
    rightError = rightTargetMps - rightSpeedMps;

    integralLeft = integralLeft + leftError * dt;
    integralRight = integralRight + rightError * dt;

    leftPwm = kp * leftError + ki * integralLeft;
    rightPwm = kp * rightError + ki * integralRight;

    leftPwm = max(-maxPwm, min(maxPwm, leftPwm));
    rightPwm = max(-maxPwm, min(maxPwm, rightPwm));

    pwmMsg.data = int16([round(leftPwm), round(rightPwm)]);
    send(pwmPub, pwmMsg);

    fprintf('dt=%.3f  left=%.3f  right=%.3f  pwm=[%d %d]\n', dt, leftSpeedMps, rightSpeedMps, pwmMsg.data(1), pwmMsg.data(2));
end

5. Tune the Controller

  • Start with ki = 0 and increase kp until the wheels respond quickly.
  • Then increase ki gradually to remove steady-state error.
  • If the robot oscillates, reduce kp or ki.
  • Use the MATLAB terminal output to observe measured wheel speed and PWM output in real time.

6. Validate Behavior

To test your controller, run the robot with the wheels lifted first. Confirm that the robot responds to your MATLAB loop, then place it on the floor and verify that the wheel speed tracks your target.

You can use the LED topic to show status if you want a simple visual indicator during tuning.

Verification Tasks

Verification Test Expected Result
Bridge Bring-up The astar_bridge node runs successfully on the Pi and publishes encoder data.
MATLAB PI Loop Your MATLAB script subscribes to encoder ticks and publishes PWM commands continuously.
Controller Tuning The measured wheel speed approaches the target speed with stable behavior and no severe oscillation.
